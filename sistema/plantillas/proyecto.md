# Plantilla de proyecto

Ubica el proyecto por su propósito y comienza con un solo archivo cuando sea pequeño. Si necesita una carpeta, conserva el ID y el contenido vivo en una nota explícita como `estado.md`. El README queda como portada y enlaza esa nota sin duplicar su estado.

```markdown
---
id: n-<new-uuid-v4>
tipo: proyecto
estado: en-curso
actualizado: "YYYY-MM-DD"
resumen: "<Una oración que describa el proyecto.>"
aliases: []
---

# <Nombre del proyecto>

## Objetivo

<Resultado buscado y ámbito principal.>

## Estado vigente

<Qué existe, qué está probado, qué se publicó y qué sigue pendiente, con evidencia.>

## Contexto y alcance

<Motivo, límites y relaciones con otros ámbitos sin duplicar su contenido.>

## Decisiones confirmadas

<Fecha, autoridad, evidencia y alcance. Separa las propuestas abiertas.>

## Próximo paso y pendientes

<Acción concreta para retomar y bloqueos reales.>

## Cambios significativos

<Hitos, resultados e histórico local enlazado cuando haga falta.>

## Fuentes relacionadas

<Documentos de Nexo y sistemas originales que acreditan el estado.>

## Fuentes y archivos

<Sección opcional. Nombre, fecha relevante, función, enlace directo e ID disponible. Reutiliza el original y conserva cada documento histórico.>
```
